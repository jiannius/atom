# Laravel 13 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bump `jiannius/atom` to support Laravel 13 (hard cut, drop L12) while keeping Livewire on 3.x.

**Architecture:** Three thin tasks — `composer.json` edits, one-line code fix in a Builder macro for L13's new cache serialization default, and a `composer update` to regenerate the lockfile. A fourth task performs manual verification in a fresh Testbench 11 host since this repo has no test suite.

**Tech Stack:** PHP 8.3+, Laravel 13, Livewire 3.x, Volt 1.x, Orchestra Testbench 11.x, Composer 2.

**Spec:** `docs/superpowers/specs/2026-05-12-l13-upgrade-design.md`

**Note on TDD:** This package has no test suite (Testbench is in `require-dev` but unused). The TDD loop in the broader writing-plans skill is replaced here by composer-level resolution checks and the manual verification task at the end. Do NOT add a new test framework in this plan — that's an unrelated initiative.

## Task 2: Fix `tableColumns()` macro for L13 cache serialization

**Why:** L13's default `serializable_classes: false` rejects deserializing arbitrary classes from cache. `DB::select("show columns from ...")` returns `stdClass` rows, which would be rejected on read after the first cache hit. Casting rows to arrays before caching avoids the issue with no behaviour change.

**Files:**
- Modify: `/Users/tj/Projects/jiannius/atom/src/Macros/Builder.php` (line 88, inside the `tableColumns` macro)

- [ ] **Step 1: Read the current macro**

Run: `sed -n '81,95p' /Users/tj/Projects/jiannius/atom/src/Macros/Builder.php`

Expected current code:
```php
    /**
     * Get table columns
     */
    public function tableColumns()
    {
        return function () {
            $table = $this->getModel()->getTable();
            $columns = cache()->remember('table_'.$table.'_columns', now()->addDays(7), fn() => DB::select("show columns from `$table`"));

            return collect($columns)->map(fn($val) => [
                'name' => data_get($val, 'Field'),
                'type' => data_get($val, 'Type'),
            ])->values();
        };
    }
```

- [ ] **Step 2: Edit the cache closure to cast rows to arrays**

Replace the `$columns = cache()->remember(...)` line with:

```php
            $columns = cache()->remember('table_'.$table.'_columns', now()->addDays(7), function () use ($table) {
                return collect(DB::select("show columns from `$table`"))
                    ->map(fn ($row) => (array) $row)
                    ->all();
            });
```

The downstream `data_get($val, 'Field')` / `data_get($val, 'Type')` calls work unchanged on array rows (MySQL column metadata keys `Field`, `Type`, `Null`, `Key`, `Default`, `Extra` survive the cast).

- [ ] **Step 3: Lint-check the file by syntax-checking it**

Run: `php -l /Users/tj/Projects/jiannius/atom/src/Macros/Builder.php`

Expected output: `No syntax errors detected in ...`

- [ ] **Step 4: Bust any existing cached entries on local dev environments**

This is a note for downstream consumers, not a step to run here — they should `php artisan cache:clear` after upgrading because the previously-cached `stdClass` values won't be readable under the new default.

Add a one-line note to the spec/release-notes section if you tag a release from this work.

- [ ] **Step 5: Commit**

```bash
cd /Users/tj/Projects/jiannius/atom
git add src/Macros/Builder.php
git commit -m "$(cat <<'EOF'
fix: cast tableColumns rows to arrays before caching

L13 sets serializable_classes to false by default, so cached
stdClass rows from DB::select would fail to deserialize on
read. Plain arrays bypass the new default; downstream
data_get() calls work unchanged.

Consumers upgrading to Atom on L13 may need to run
`php artisan cache:clear` once to drop stale stdClass entries.
EOF
)"
```

Expected: commit created, working tree clean for `Builder.php`.

## Task 4: Manual verification in a fresh Testbench 11 host

**Why:** The repo has no automated tests. We exercise the package against a real L13 boot to confirm it installs, service-provider boots, and the surfaces we care about respond correctly.

**Files:** none modified in this repo; verification is performed in a scratch directory outside the repo.

- [ ] **Step 1: Create a scratch host app with Testbench 11**

Run, replacing `<SCRATCH>` with a directory of your choice (e.g. `/tmp/atom-l13-verify`):

```bash
SCRATCH=/tmp/atom-l13-verify
rm -rf "$SCRATCH"
composer create-project orchestra/testbench-skeleton "$SCRATCH" --no-interaction \
  --stability=stable --prefer-dist
cd "$SCRATCH"
composer require "laravel/framework:^13.0" --no-interaction
```

Expected: a scaffold directory with `vendor/`, `testbench.yaml`, and a `workbench/` folder.

- [ ] **Step 2: Add the Atom repo as a path repository and require it**

From `$SCRATCH`:

```bash
composer config repositories.atom path /Users/tj/Projects/jiannius/atom
composer require jiannius/atom:@dev --no-interaction
```

Expected: install succeeds. `composer show jiannius/atom` reports the package is installed at the path.

- [ ] **Step 3: Boot the package and dump the service provider**

Run from `$SCRATCH`:

```bash
vendor/bin/testbench package:discover
vendor/bin/testbench tinker --execute='dump(app("atom") instanceof \Jiannius\Atom\Atom);'
```

Expected:
- Package discovery output mentions `jiannius/atom`.
- Tinker output ends with `bool(true)`.

- [ ] **Step 4: Confirm the container binding and route registration**

`toast()` / `modal()->show()` both dispatch on the current Livewire component, so they cannot be exercised from tinker (no live request). Instead, verify the wiring:

From `$SCRATCH`:

```bash
vendor/bin/testbench tinker --execute='
dump(app("atom") instanceof \Jiannius\Atom\Atom);
dump(app("atom")->modal("x") !== null);
$routes = collect(app("router")->getRoutes()->getRoutes())
    ->map(fn ($r) => $r->methods()[0] . " " . $r->uri())
    ->filter(fn ($u) => str_contains($u, "atom/"))
    ->values()
    ->all();
dump($routes);
'
```

Expected:
- First two dumps print `bool(true)`.
- The route list contains at least `GET atom/{file}` and `POST atom/action/{name}`.
- No exceptions.

If anything throws, capture the exception, stop, and report — that's an L13 regression to investigate.

- [ ] **Step 5: Exercise the `GetOptions` action via the public route**

The `/atom/action/{name}` route is registered by the service provider. Start a Testbench dev server in one shell:

```bash
cd "$SCRATCH"
vendor/bin/testbench serve --port=8765 &
SERVER_PID=$!
sleep 2
```

In another shell, hit the endpoint:

```bash
curl -s -X POST http://127.0.0.1:8765/atom/action/GetOptions \
  -H 'Content-Type: application/json' \
  -d '{"name":"countries"}' | head -c 500
```

Expected: a JSON response containing an array of country options (the package ships `json/countries.json`). If you get a 404 or 500, capture the response body and the Laravel log under `$SCRATCH/storage/logs/` and stop.

Kill the server: `kill $SERVER_PID`.

- [ ] **Step 6: Exercise the `tableColumns()` cache fix**

From `$SCRATCH`, create a tiny migration + model and run the macro. In tinker:

```bash
vendor/bin/testbench tinker --execute='
Illuminate\Support\Facades\Schema::create("verify_cols", function ($t) {
    $t->id();
    $t->string("name");
    $t->timestamps();
});
$model = new class extends \Illuminate\Database\Eloquent\Model {
    protected $table = "verify_cols";
};
// Call twice — first populates cache, second reads it back.
dump($model->newQuery()->tableColumns()->all());
dump($model->newQuery()->tableColumns()->all());
'
```

Expected: both `dump()` calls return the same collection of `['name' => ..., 'type' => ...]` arrays without throwing. If the second call throws an `UnserializableValueException` or similar, the cache fix is wrong — go back to Task 2.

Note: Testbench defaults to the SQLite in-memory driver. `show columns from` is MySQL syntax. If the verification fails with a SQL error rather than a serialization error, point Testbench at a MySQL connection (`DB_CONNECTION=mysql` in `$SCRATCH/.env.testing`) before re-running this step — or skip this step and rely on the consumer-side smoke test for `tableColumns()`.
