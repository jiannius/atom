# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`jiannius/atom` is a Laravel package (composer name `jiannius/atom`, PSR-4 namespace `Jiannius\Atom\`) that ships a Tailwind + Alpine + Livewire UI component library. It is consumed by other Laravel apps via `composer require`; this repo is the library itself, not a host app. There is no `.env` and no host app; tests boot the package through Orchestra Testbench (see Tests and CI).

## Common commands

```bash
# Build front-end assets (Vite) → dist/assets + dist/manifest.json
npm run build

# PHP deps
composer install

# Tests (see "Tests and CI" below)
vendor/bin/pest                    # Pest + Testbench
npm run test:e2e                   # Playwright against `vendor/bin/testbench serve` (:8000)
node tests/consumer/build.mjs      # compile the consumer Tailwind fixture (after `npm ci` in tests/consumer/floor and /latest)
```

There are no lint or dev-server scripts defined. `vite.config.js` uses `laravel-vite-plugin`, but the package has no host Laravel app to serve from — `npm run build` produces a static `dist/` that is committed and served at runtime via the package's own `/atom/{file}` route.

### Tests and CI

- **Pest** (`tests/Feature`, `tests/Unit`) runs on Orchestra Testbench; `composer.lock` is not tracked, so dependencies resolve fresh. **Playwright** (`tests/e2e`) drives the testbench-served app: `/atom/docs` and the fixtures under `/atom/e2e/*` (`tests/Fixtures/E2EServiceProvider.php`).
- **CI** (`.github/workflows/ci.yml`, on push to `main` and on pull requests): Pest on PHP 8.3 and 8.4; Playwright on Chromium only; the consumer Tailwind compile at both versions; and a `dist/` freshness check (`npm run build`, then the committed `dist/` must not change). Run `npm run build` and commit `dist/` whenever JS or CSS sources change.
- **Consumer Tailwind fixture** (`tests/consumer/`): the e2e rig has no Tailwind, so utility classes are absent from every other page. `floor/` (the hosts' minimum, 4.0.7) and `latest/` (a hand-bumped pin of the newest 4.x) each have their own `package.json` and lockfile; `node tests/consumer/build.mjs [floor|latest]` compiles `input.css` (it imports `atom.tailwind.css` the way a host does, and adds `resources/views/e2e` and `tests/Fixtures`, which `atom.tailwind.css` leaves out) into the git-ignored `tests/consumer/build/<name>.css`. A page opts in through `<atom:html :styles>`: `/atom/e2e/consumer-tailwind?tw=floor` (or `latest`), served by `/atom/e2e/consumer-css/{name}`. `tests/e2e/consumer-tailwind.spec.js` proves it.
- Run Pest before Playwright (testbench's server leaves an `.env` behind); never pipe Playwright into `tail`/`head`, the server child keeps the pipe open.

## Architecture

### Service-provider wiring (`src/AtomServiceProvider.php`)

`boot()` registers everything; read it first when something seems to come from nowhere:

- Loads `routes/web.php`, `lang/`, and `resources/views/` under the `atom` view namespace.
- Registers anonymous Blade components in `components/` under the `atom` namespace, so `components/button/index.blade.php` is reachable as `<x-atom::button>` **or** as `<atom:button>` (see Tag compiler below).
- Does **not** swap Laravel's `Date` facade (v4 removed `Date::use()`): `now()` and model dates are the host's own mutable Illuminate dates unless the host adds `Date::use(Services\Carbon::class)`. atom's own code must work on either, so wrap a date in `carbon($date)` (or `Carbon::instance()`) before calling `->local()`, `->pretty()`, `->recent()` or `->toDateRangeString()`, which only `Services\Carbon` has (`breakdown()` and `Calendar::now()` were the two internal callers that assumed the swap), and never rely on a date being immutable. `tests/Feature/DefaultDateTest.php` runs with no swap and with it.
- Mixes in macros onto Eloquent `Builder`, Query `Builder`, `Request`, `Str`, `Stringable` and `Arr` (`src/Macros/*`), plus the `Livewire\Component` helpers (see Livewire integration). Every macro is on every host's class, so each one is a public API: `tests/Feature/MacroAllowlistTest.php` collects every macro whose closure lives in `src/` and pins the set per class, so adding one fails until it is listed on purpose. `ComponentAttributeBag` is deliberately **not** macro'd (v4): the three lookups the components need are static helpers on `Services\Attributes` (`fieldId()`, `modifier()`, `hasLike()`, each taking `$attributes` first), called as `\Jiannius\Atom\Services\Attributes::fieldId($attributes, ...)`; if a component needs another attribute lookup, add it there, not as a macro.
- Boots `Services\Asset`, which exposes the public route `GET /atom/{file}` serving files from `dist/assets/` with `Cache-Control: immutable`. `atom()->asset()->version($name)` looks up the hashed filename in `dist/manifest.json`. Consuming apps reference assets by name, not path.
- Mounts a public `POST /atom/action/{name}` endpoint that the JS uses to invoke actions remotely — unauthenticated, and gated per-action by the `WebAction` contract (see "Actions" below).

### The `<atom:...>` tag syntax (`src/Services/TagCompiler.php`)

Custom Blade precompiler (inspired by livewire/flux) translates `<atom:button>`, `<atom:icon.add/>`, `<atom:button.group>` into the corresponding `<x-atom::...>` component invocations before the normal Blade compile runs. Dot-paths map to subdirectories: `<atom:button.group>` → `components/button/group.blade.php`. This syntax is preferred throughout `components/` over `<x-atom::...>`.

### The `Atom` singleton (`src/Atom.php`, aliased as `app('atom')` / via the `atom()` helper indirectly)

Single entry point for cross-cutting UI operations that need to dispatch Livewire events from PHP:

- `atom()->modal($name)->show()/slide()/close()` — dispatches `atom-modal-show` / `atom-modal-close` on the *current* Livewire component.
- `atom()->toast(...)`, `atom()->alert(...)`, `atom()->confirm(...)` — dispatch the matching `atom-toast-show` / `atom-alert-show` / `atom-confirm-show` events. All `heading`, `subheading`, `message` strings are passed through `t()` (translation helper).
- `atom()->action($name, $params)` — resolves an Action class from `App\Actions\{Name}` *or* `Jiannius\Atom\Actions\{Name}` and invokes `handle($params)` (or `$params['method']`). Its sibling `webAction()` is the gated version behind the public endpoint (see "Actions" below).
- `atom()->mail(...)`, `atom()->breadcrumbs()`, `atom()->broadcast()`, `atom()->sitemap()`, `atom()->asset()`.

The `Atom` class is registered both by FQN and by the `'atom'` container alias — both work.

### Livewire integration: component macros and opt-in traits (v4)

`AtomComponent` is gone (v4-4a, no alias). Two mechanisms replace it:

- **Helpers are `Livewire\Component` macros**, registered in `AtomServiceProvider::registerComponentMacros()`: `modal`, `command`, `toast`, `alert`, `confirm`, `wirekey`, `action`. A macro runs through `Component::__call` with the closure bound to the component (`$this->skipRender()` works), so host call sites and Blade (`$this->wirekey()`) are unchanged, and a class method of the same name still wins. Livewire checks a browser call against `Utils::getPublicMethodsDefinedBySubClass()`, which reflects real methods only, so a macro can never be called as `$wire.toast(...)` or from a crafted `calls` payload (it is a `MethodNotFoundException`). That is what keeps `action()` unreachable from the browser (see "Actions" below); `tests/Feature/ComponentTraitsSurfaceTest.php` proves it with real update requests. **Never turn a helper back into a trait method.**
- **State is in four opt-in traits** in `src/Traits/`, one bucket each (Livewire names a trait's hooks after it, so they are `mountWith*` / `updatingWith*` / `updatedWith*`):
  - `WithTable`: `$_table` (sort, checkboxes, select_all, max_rows, show_trashed, show_selected), the table methods and `updatedWithTable()` (trashed toggle clears the selection). The signed `raw:` gate is **not** in the trait: it is a listener in the service provider (see Signed `raw:` table sort). No `WithPagination`: `toggleTableShowSelected()` calls `resetPage()` only when the component has it.
  - `WithBreadcrumbs`: `$_breadcrumbs`, built by `mountWithBreadcrumbs()` from an optional `breadcrumbs()` method.
  - `WithEditor`: `$_editor.images`, `WithFileUploads`, `updatedWithEditor()` (see Editor flow below).
  - `WithRecaptcha`: `$_recaptcha`, `verifyRecaptcha()`.

`WithPagination` is no longer forced; a paginated table component adds Livewire's own.

**Missing-trait errors.** `Atom::requireTrait($trait, $for)` throws a `LogicException` naming the trait and `get_class($component)` when the component whose view is rendering lacks it, and does nothing when none is. "Rendering" is Livewire's `HandleComponents::$renderStack` (pushed around a component's view render on the initial render, every update, nested children and lazy loads), **not** `app('livewire')->current()` alone, which is also set during mount, hydrate and actions: `Blade::render('<atom:table>')` in an action (an export, a PDF, a mail body) must not throw. Static pages and the docs demos have no stack either. Two guards: Livewire before 4.4.8 pops the render stack without a `finally`, so a view that throws leaves a stale entry that outlives the request on Octane or a queue worker, hence the top counts only when it is also `current()` (the component stack is popped in a `finally`); and an island render never pushes the stack but shares `__livewire` with its view, so `app('view')->shared('__livewire')` is read as the fallback, again only when it is `current()`. If `HandleComponents::$renderStack` ever disappears, nothing is checked (`property_exists` guard). The gap this leaves: a `render()` that returns an already-rendered string (`Blade::render()` called inside `render()`) runs before the push and is not checked; return the template string or a view instead. It is called from the top of `table/index`, `table/column` (only with `sort` or `checkbox`), `table/cell` (only with `checkbox`), `table/trashed`, `table/pagination` (also `WithPagination`), `tiptap/toolbar/image` and `form` with `recaptcha`. `<atom:breadcrumbs>` renders in the layout, outside any component, so its check is a Livewire `mount` listener in the service provider (`registerComponentGuards()`): a component with a `breadcrumbs()` method and no `WithBreadcrumbs` throws at mount, since nothing would call the method. The listener skips a method that takes no parameter (v3 passed the builder in), a method carrying a Livewire attribute (a `#[Computed]` property named `breadcrumbs`) and a component, or an inherited method, whose file is under an installed Composer package: `packageRoots()` realpaths `\Composer\InstalledVersions` install paths (root package excluded), so a path-repository symlink and a custom `vendor-dir` count, plus `base_path('vendor')`. A host's own modules installed as Composer path packages are skipped too (documented in UPGRADE). A new blade that reads `$wire._table`, `_editor` or `_recaptcha` must call `requireTrait` the same way.

**`toTable()` trusts `_table` only from a component that uses `WithTable`** (`class_uses_recursive`, not `property_exists`). A host's own public `$_table` has no sort gate, so a client could `set('_table.sort.column', 'raw:...')`, and an unsigned `raw:` reads as PHP-set and trusted: the #54 injection through a component that never opted in. Any other component gets no sort and the default row count (it does not throw: it can be a plain paginated list).

**A property or method named like a trait hook.** Livewire runs `updatingWithTable`-style hooks for a property called `withTable` too, with the value where the path goes, and a host method of that name takes the place of a trait's. So no gate lives in a trait hook; the hooks that remain (`updatedWithTable`, `updatedWithEditor`, `WithUrlFilters`) start with an `is_string($name)` guard (an array there was a `TypeError`); keep it in any new hook (`HookNamedPropertiesFixture`, `SortGateShadowFixture`, `ComponentTraitsSurfaceTest`).

### Signed `raw:` table sort

`$_table.sort.column` is a plain public property (no `#[Locked]`), so a client can `$wire.set()` it to anything. A plain column name is safe either way — `toTable()`'s `orderBy()` path lets Laravel quote it — but a `raw:` value (declared as `<atom:table.column sort="raw:some_sql_expr">`) goes straight into `orderByRaw()`, so a tampered one is SQL injection (issue #54: boolean-blind exfiltration via row order). `components/table/column.blade.php` signs a `raw:` value before it ever reaches the browser — `Services\TableSort::sign($expression)` HMACs it (against `config('app.key')`) into `raw:<64-hex-hmac>:<expression>` — and that signed string is what the Alpine click handler round-trips through `$wire.set('_table.sort.column', ...)`. The gate is a listener on Livewire's `update` event, registered with `\Livewire\before()` (not `on()`: a host's `updating()`, `updatingTable()` or `updatingTableSortColumn()` hook shares the event and, running first, would see and could store the unsigned value) in `AtomServiceProvider::registerComponentGuards()` for every component that uses `WithTable` (`TableSort::isUnsafeUpdate()` holds the rules). It was a trait hook (`updatingWithTable`) until a review showed a host method of that name, such as Livewire's ordinary hook for a `$withTable` property, silently replaced it while `toTable()` still trusted `_table`. `update` fires from `HandleComponents::updateProperty()` before the value is written, for every client update path (`$wire.set`, wholesale `_table`, `$set`, `$toggle`, and a file upload naming its target property), and a host hook cannot unregister it. It checks `str_starts_with($path, '_table')` before `class_uses_recursive()`, so other properties cost one string test. A value read from the URL goes through no `update` event (BaseUrl writes it before `mount()`), so the mount listener also throws for a `WithTable` component whose query-string config has a key `_table` or under it: a `queryString` property or method, any used trait's `queryString{Trait}` member, or `#[Url]` on a redeclared `_table` (the forms `SupportQueryString` reads). It inspects `_table.sort.column`, `_table.sort`, and `_table` wholesale (the event fires once per dotted path a `$wire.set()` targets, so all three shapes need checking) and refuses (403) any client update that would leave an unsigned or tampered `raw:` value there. The gate only runs for a client-originated update — a host mounting `_table['sort']['column'] = 'raw:...'` directly in PHP never touches Livewire's `update` event, so an *unsigned* `raw:` value reaching `toTable()` can only have come from PHP and stays trusted; `TableSort::expression()` verifies a signed one and strips the signature before it reaches `orderByRaw()`, returning `null` (no sort applied) on a bad signature. The sort direction on that branch is also clamped to `asc`/`desc` there (anything else defaults to `asc`) since it used to be spliced into the raw SQL unvalidated too.

### `filter()` keys and values are untrusted

`Builder::filter()` (`src/Macros/Builder.php`) is fed `$this->filters`, the README's plain public array. Livewire lets a client replace a public property wholesale (`$wire.set('filters', {...})`), so both keys and values are client-controlled. It was a boolean-blind SQL injection once: the date branch checked the column type on the key's part before the first dot but interpolated the whole key into `DB::raw("date(...)")` (MySQL only, because the type comes from `show columns`; issue #86, PR #96). What the macro gates now:

- **Key shape.** After the scope branch, a key must be `col`, `col:operator` or `col.path` (JSON columns only), matching `^[A-Za-z_][A-Za-z0-9_]*(\.[A-Za-z0-9_]+)*$`. Anything else, a dotted key on a non-JSON column, a second `:`, a non-string/int key: no-op, before any column introspection. A digit-leading or hyphenated column, or a JSON segment with `-` or `[0]`, is therefore skipped.
- **Operator.** Only `= != <> < <= > >= like` and `not like` (case-insensitive). Laravel's own list (`regexp`, `rlike`, bitwise, `is`...) is refused: no-op, not "demoted to `=`".
- **Hidden and non-visible columns.** A key whose first column segment is in `getModel()->getHidden()`, or, when `getVisible()` is non-empty, not in it (both case-folded), is skipped (`$visible` is a serialisation list, so one that omits `created_at`, `status` or a foreign key silently drops filters on them), so `like` or `>=` cannot be used as a row-set oracle against a password or token. Only the model's `$hidden` / `$visible` properties are read: `makeHidden()` on an instance and unlisted sensitive columns are not seen.
- **Date columns** go through `whereDate()` (quoted identifier); never interpolate a key or column into raw SQL. Datetime/timestamp use `where()`. A `DateTimeInterface` value stays an object (Laravel formats and binds it) and skips the `x to y` string test; only a string or `Stringable` is cast.
- **List values.** On a plain column `=`/no operator is `whereIn` ("one of", dates allowed in the list), `!=`/`<>` is `whereNotIn`, an ordering operator or `like` is a no-op. `like` with a date object is a no-op on a plain column only; on a date column `like` goes to `whereDate` like any other operator. On a JSON column a list is `whereJsonContains` (contains ALL of the list, not one of it) for `=`/no operator and `whereJsonDoesntContain` (does not contain all) for `!=`/`<>`.
- **Value shape.** A value that is not a scalar, array, `Stringable` or backed enum, an array on a date column or a `like`, a nested array in `whereIn`/an enum list, or an array for `search`: no-op, never a 500. The fuzz in `tests/Feature/FilterMacroTest.php` runs value shapes x keys x operators against a MySQL grammar (no server needed) and asserts a placeholder per binding.

What it does **not** gate: any other column the model does not hide, and any named scope, which is invoked with the value as the client sent it, whatever its shape (string, array, date; so a scope's own typed signature can still throw). A host that needs more passes only allowed keys (`filter(Arr::only($this->filters, [...]))`); it must not `#[Locked]` a `$filters` that atom's table controls `wire:model`, since Livewire refuses every client update to a locked property; the README says so. Any new branch in `filter()` must keep the same rules: no key or column in raw SQL, validate before introspecting, and add the shape to the fuzz.

### Filters in the URL: `Traits\WithUrlFilters` (issue #86)

Opt-in trait (`src/Traits/WithUrlFilters.php`): the host declares `urlFilters(): array` (key => default), optionally `urlFiltersExcept()` (internal keys), `isUrlFilterValid()`, `urlFiltersProperty()`, `urlFiltersPrefix()`; the trait emits one dotted `queryString{Trait}` entry per key (`'filters.status' => ['as' => 'status', 'history' => false, 'except' => $default]`; the spike on Livewire 4.3 confirmed PHP seeding, key removal in JS, `Livewire::withQueryParams()`, and that `history: false` becomes `use: replace`). A host that does not use it is untouched. What to know before changing it:

- **The declaration is an allow-list and is enforced where a value arrives, two ways on purpose.** The URL is read into `$filters` by `BaseUrl` with `data_set()` BEFORE the host's `mount()` (SupportQueryString runs before the lifecycle hooks), which never fires an `updating*` hook, so `mountWithUrlFilters()` (after `mount()`) is the only gate for it and it DROPS silently (undeclared key removed, a wrong shape or a host-refused value reset to the default): a link someone crafted must open the listing, not 500 it. `updatingWithUrlFilters()` gates every browser update and REFUSES (403, like the signed `raw:` sort): it checks `filters` (every key and value of the replacement), `filters.x` and refuses anything deeper (`filters.x.0`; a list is only ever replaced whole, and a deeper path is how a scalar turns into an array). **An `is_string()`-only gate was once bypassed by an array value; the shape check is scalar/null for a scalar default and a LIST of scalars for a list default, and a list default must be `[]`.** It covers named-scope keys and plain columns alike because neither reaches `filter()` unless declared. `#[Locked]` is not an option: the table controls bind `wire:model="filters.*"` and Livewire throws on any client update to a locked property.
- **Values the page cannot carry are refused on both paths** (`urlFilterShapeMatches()`): a string that is not valid UTF-8 (`?search=%FF` made Livewire throw "Malformed UTF-8" serialising the snapshot: a crafted-link 500), over `urlFilterMaxLength()` bytes (1000), or a list over `urlFilterMaxItems()` (200, a `whereIn()` placeholder limit). A throw from the host's `isUrlFilterValid()` (a date parse) is caught and counts as a refusal on both paths: it is a crafted-URL 500 otherwise. It is also logged, not `report()`ed: `Log::warning` with the component, key, exception class and `file:line`, NEVER the exception message or the value (Carbon's message quotes the value, up to 1000 bytes the visitor chose: log-line forgery, and it would go to Sentry/Flare). Deduped across PHP-FPM workers with `Cache::add('atom:url-filter-failure:'.md5(component|key|exception), 1, 3600)` (once an hour); if the cache throws, or cannot remember (the null store: `add()` false and `has()` false, which would otherwise never log; `reportUrlFilterFailure()`), the static `$urlFilterReported` set, capped at 100 and emptied when full like `Content::$logged`, is the per-process fallback. The testbench default cache is the database store with no table, so a test sets `cache.default` to `array` (and the fallback is what runs otherwise). The host's own `mount()` runs BEFORE the clean-up, so it sees raw URL values (documented). `queryStringWithUrlFilters()` throws a `LogicException` for a key (with prefix) that collides with `page` (ONLY when the class uses Livewire's `WithPagination`, a v4 component adds it itself; Livewire adds `page` to `$paginators` lazily, so no entry exists at mount), the host's `queryString`, another trait's or a `#[Url]` property (inside the trait `self::class` is the USING class, so skip itself with `__TRAIT__` or it recurses forever).
- **`tab` is not reserved by name** (it was, until #100): atom has no `tab` query key of its own (`<atom:tabs>` writes none), so a host's tab is a `#[Url]` property or a `queryString` entry and the checks above already find it; a filter called `tab` on a component with neither is fine. **A custom paginator page name is checked after mount, not at it, and on the initial render only**: Livewire registers a page name in `$paginators` when the paginator is built (`->paginate(10, pageName: 'p')`, `LengthAwarePaginator` with `pageName`), during render, so `dehydrateWithUrlFilters()` (a no-op when `$paginators` is empty) throws the same `LogicException` when a filter key with its prefix equals a page name. **`$paginators` is a public, client-writable property**, so on an update request (`$wire.set('paginators.search', 3)`, `$wire.set('paginators', {status: 1})`, `$wire.gotoPage(2, 'region')`) the same check was a 500, reported on every request, for something harmless before: it is skipped there, and a name the host registers only on a later request is not caught. "Initial render" is the protected `$urlFiltersMounted`, set by `mountWithUrlFilters()` (every update request hydrates a fresh instance, so it is false): not `Livewire::isLivewireRequest()`, which is only `request()->hasHeader('X-Livewire')`, a header a client can leave off. **`WithoutUrlPagination` changes neither rule**: `SupportPagination::ensurePaginatorIsInitialized()` skips only the URL write (`addUrlHook()`), it still calls `resolvePage()` (`request()->query($alias)`), so with a paginator named `search` and `?search=ap` `$paginators` is `{"search":"ap"}` and `nextPage('search')` is a `TypeError` (the same for a `page` filter and `?page=abc`); such a component still reserves `page` and is still checked (a first version skipped it, a re-review caught that). What the collision does on Livewire 4.3 without it: both entries get `as => search` (`paginators.search` is `push`, `filters.search` is `replace`) so the last writer owns the URL, `?search=ap` seeds `paginators.search = 'ap'` and `nextPage('search')` is a `TypeError` ("string + int"), and `?search=2` filters on "2" and opens page 2. On the initial request the LogicException reaches the host wrapped in a `ViewException` (the render is inside the view), so a test walks `getPrevious()`. A page name that is an alias set in the host's `queryString` (`paginators.x => ['as' => ...]`) is not compared; only the name. The hook is public because Livewire's `callTraitHook` cannot call a protected one (`Method ... does not exist`).
- **Internal keys survive a wholesale `$wire.set('filters', {...})`**: `updatingWithUrlFilters` stashes them, `updatedWithUrlFilters` merges them back (a replacement is not able to wipe a tenant scope), and the browser can never set one. The same hook fills any declared key a replacement left out (`set('filters', [])`) with its default.
- **`except` is the declared default**, so a filter back at its default leaves the URL (JS `track()`); `null`/`''` as "All" is why a non-null default needs `''` for "All" (null is stripped, so a reload brings the default back). A key is a plain identifier: PHP rewrites `.` and spaces in a query key, and a dot would also address a nested path.
- **Livewire reads a list as `status[0]=a`**; its JS rewrites a hand-written `status[]=a` on load.
- **The crumb and Back come back with the filters only when the trail survives `wire:navigate`** (`@persist('breadcrumbs')`, see Breadcrumbs): `breadcrumbs.js` `back()` and the crumb read the `href` captured in `getLatestHref()`. `tests/e2e/url-filters.spec.js` proves crumb, Back and the browser Back; removing the `@persist` turns the first two red.
- **Not a replacement for `filter()`'s checks or for `filter(Arr::only(...))` on a component without the trait.** Sort is not persisted; if it ever is, re-check `_table.sort.column` in `mountWithUrlFilters()` with `TableSort::isUnsafeFromClient()` (URL values skip the `update` listener).
- Tests: `tests/Feature/UrlFiltersTest.php` (fixtures `UrlFilters*Fixture`), `tests/e2e/url-filters.spec.js`. Each gate was mutation-checked (removed one at a time, a test goes red; the reserved-`page` condition, the paginator check with and without the prefix, its initial-render gate for each client shape, `WithoutUrlPagination` still reserving and checking, the log, each part of the dedupe key, its TTL, the message-free context, the fallback set, its cap and the refusal included), except the `str_contains($path, '.')` clause in `updatingWithUrlFilters()`, which is defence in depth that the undeclared-key check makes unreachable today.

### Editor content lifecycle (Tiptap + Livewire uploads)

A subtle, two-phase flow worth understanding before touching the editor:

1. While the user types, image uploads land in Livewire's temporary disk and are echoed back into `_editor.images` as `temporaryUrl()` strings (handled in `WithEditor::updatedWithEditor()`). The editor HTML carries `<img src="/livewire-{hash}/preview-file/...">` URLs (Livewire 4 prefixes internal URLs with an APP_KEY-derived hash).
2. Only when the editor's column is *saved* through Eloquent does `Casts\AsTiptapContent::set()` walk the document's image nodes, resize each `/livewire-{hash}/preview-file/` URL via Intervention Image (max width 1000, q=80), persist it to `config('atom.editor.disk')` (the default disk when unset) under `<configured folder>/editor/`, rewrite the URL, and store the JSON. (`AsEditorContent`, the v2 cast that did this for HTML, is deleted in v4.)
3. Stored values are Tiptap JSON; legacy rows (the old `AsEditorContent` cast) are `serialize()`d HTML or `serialize()`d JSON, and `AsTiptapContent::get()` unserializes lazily, falling back to the raw value if it isn't serialized: the dual-read path, so a host never has to migrate in one step. Every unserialize (the cast, `atom:tiptap-migrate`, the purge command's backup scan) goes through `Tiptap\Content::unserialize()`, which passes `allowed_classes => false`: a payload holding an object (at any depth) reads back as `null`, never as an instance. `AsTiptapContent::set()` also refuses a client-sent serialized string (a serialized HTML string is unwrapped, any other serialized value is dropped). Stored content is untrusted on the render side too: `Content::render()` reports and renders empty on a document it can't handle, and every value that reaches `style`, `class`, `target`/`rel` or an iframe `src` is checked against an allowlist — `Tiptap\StyleValue` plus the `Atom*` extensions in `src/Tiptap/Extensions/` (`AtomColor`, `AtomHighlight`, `AtomTextAlign`, `AtomLink`, `AtomCodeBlock`, `AtomImage`, `FontSize`, `Youtube`). A new extension that renders a stored attribute must validate it the same way.
4. **What the browser sends is untrusted too, and atom can't intercept the host's storage.** The chat composer (`<atom:tiptap.chat>`) hands the host raw `tiptap.getHTML()` in an `input` event (`{ body, files }`), and any client can call `$wire.submit()` with its own string. `Content::sanitize(mixed $html, int $maxBytes = 131072, int $maxTags = 5000): string` is the host's gate **for HTML (chat mode)**: it parses the value through the same `Content::extensions()` as `render()` (one list, so the two can't drift) and returns the schema's own serialisation, so a script, handler, failing `style`/`class`, `javascript:`/`data:` href, non-YouTube iframe or unknown tag can't come back out. It is not for the JSON editor: `<atom:tiptap>` / `AsTiptapContent` store JSON, which `render()` already prints safely, and sanitising it would turn the column into HTML and drop YouTube. A host must `sanitize()` chat HTML before storing, or print through `<atom:tiptap.content>` / `Content::render()`, and never through `x-html` or `{!! !!}` straight from the column; rows stored before it adopts `sanitize()` stay unclean until it renders them through `render()` or backfills them. It returns `''` for empty, refused and failed input alike (`Content::sanitizeRefuses()` tells a refusal apart). Refusals are silent, so a client can't flood the log; only an unexpected exception is `report()`ed. So is input with nothing to render: `convert()` asks `hasBody()` first (libxml builds no `<body>` for a script, style, comment, bare `<meta>`/`<link>`/`<base>`/`<title>`, `<html></html>` or whitespace, which Minify's Unicode-aware trim also empties, so it loads what the parser loads, minified) and returns `''`, since tiptap-php's parser throws a `TypeError` on a bodyless document; and `dedupeMarks()` folds the marks of one type on a node into one (attributes merged, a later value winning only for the same key, a later null never blanking an earlier value, a `link` keeping its first href that passes the allow-list), because the serialiser's mark stack throws an `ErrorException` on `<code>><code>c` or `<p><strong>a<em><strong>c</strong></em></strong></p>`, and printed nested duplicate tags for simple repeats such as `<code><code>c</code></code>`; last-wins would drop a `textStyle` colour when an inner span adds nothing, so merge, do not replace. Content that is only whitespace, Unicode spaces (U+3000, no-break) included, is `''` too. `tests/Feature/ContentEmptyInputTest.php` holds both. Input that is not a string, a `Stringable`, or an array with a `type` key is `''`; any string that is not a JSON document (`'42'`, `'null'`) is text. **The cost limits are the DoS defence, and they live in the shared `convert()`.** Parsing cost tracks the tag count, not the bytes (about 3 KB of memory per tag worst case; 65,536 `<p>a` was 212 MB and 2.7 s, a fatal at 128M), so `inspect()` refuses HTML over `maxBytes` (128 KB), over `maxTags` `<` characters (5000: worst shape ~16 MB and ~0.2 s), or carrying tiptap-php's `MINIFYHTML` placeholder, and `convert()` refuses output over 4x `maxBytes` (a small `maxBytes` caps the output at 4x that). `sanitize()` (only; `render()` reads content stored under its own limits) also refuses output with more than `maxTags` `<` characters: a document prints up to four tags per node, so about 5000 empty tables (85 KB) were about 20,000 tags out, stored and printed on every view; real composer output prints exactly as many tags as it had, a long article about 0.9 per node, and what can trip it is hand-written HTML that leans on the parser (`<p><b>a</b>x` prints four tags for three). `convert()` and `sanitizeRefuses()` both go through `attempt()` (which returns `[html, refusal, text]` and throws on a failure), so the two agree: `sanitizeRefuses()` converts input that passes the cheap checks to measure the output, and its worst-case cost is one more parse. Measured at the defaults, about 1,250 list items or a 5-column table of about 228 rows reach the output cap (the byte limit is close behind); a checklist- or table-heavy field raises `maxTags` and `maxBytes`. **`Content::resanitize(string $html)` is the backfill for stored HTML that an earlier `sanitize()` wrote from JSON** (rows with stray markup from the zero-attribute hole): `sanitize()` over such a row would drop its YouTube embeds (HTML parsing drops every `<iframe>`), so `resanitize()` sets aside only a `YOUTUBE_EMBED` match, which is what the `Youtube` extension prints byte for byte (`div` + `iframe` with its fixed attributes, `www.youtube(-nocookie).com/embed/<11-char id>[?start=N]`), as `<p>ATOMEMBED<random hex>x<n>x</p>`, sanitizes the rest, and puts each back only where its placeholder came out as a paragraph of its own (one inside an attribute, or a `<pre>`, is removed, and embeds inside a `<pre>` are never set aside). The token is `ATOMEMBED` plus `random_bytes(16)` in hex, from `embedToken()`, new per call: there is deliberately **no refusal of input that contains the word or the prefix** (that would let a hostile pre-fix row opt out of the repair by including it, and send genuine rows that mention it to review); only a row holding this call's own token is refused, which chance cannot produce, and leftover-stripping removes only this call's keys. It also bails out with `''` before matching anything when the row is over `$maxBytes`. **Never skip a backfill row because it contains an `<iframe>`**: a hostile row can hold one (an `srcdoc`), which is how an earlier README draft left it live. `tests/Feature/ContentResanitizeTest.php` ties `YOUTUBE_EMBED` to what `sanitize()` prints, runs the README backfill snippet against a table, and has old hostile output (captured from 3.29.13) for every shape. A JSON document is bounded the same way by node count (`documentProblem()` counts nodes and marks against `maxTags`; a `{` count spares `json_decode()` a document that is over it anyway): `{"type":"paragraph"}` x 95,000 is 2 MB and used to fatal at 128M (~3 KB per node). `inspect()` also validates the document shape: a value that is not a document (root not a `doc` with a `content` list, a non-string `type`, `content`/`marks` not lists, `text` not a string) is a silent refusal, and `report()` is only left for a failure nobody expected. **Where real content could trip a guard, it is normalised, not refused.** Attributes tiptap-php throws on are repaired in `normaliseAttributes()` so the rest of the document renders: a heading `level` that is not an int 1 to 6, or a string that is exactly one of those digits once trimmed, becomes 1 (tiptap-php checks it with a loose `in_array()` and interpolates it as sent into the tag name: `" 1"`, `"+1"`, `"6 "` threw `createElement('h holding anything but whole numbers and nulls are dropped, and a mention `label` or `id` that is an array, or an `attrs` that is not a keyed array, is dropped. **A zero in any attribute (an int `0`, or The cost tests therefore cannot use thousands of nested `<pre>`: they use ~150 over a long text run. **Nothing the minifier does after `inspect()` may join text that `inspect()` checked.** tiptap-php's `Minify` runs on the string `inspect()` returns, and its per-line trim (`^\s+|\s+$` with `m`) deletes a whitespace run holding two or more `\n` outright (CRLF becomes `\n` first; Unicode spaces count), so `<`, a blank line and `?span>` (an instruction on 2.9, a tag name on every libxml), or `MINI`, a blank line and `FYHTML<hash>0` (a forged placeholder, which expands once per token: 1,478 of them in 131 KB was a memory fatal), were fused AFTER the checks passed. `collapseWhitespace()` therefore also turns a run with two or more newlines, outside a `<pre>` (blank lines in a code block are kept), into one space. 5. `atom:purge-editor-images` reads columns cast as `AsTiptapContent` and moves anything in the editor folder that isn't referenced to `editor-purged/` on the local disk before deleting it. Rules worth knowing before touching it:
   - **What is inside a column is not assumed from its cast.** `<atom:editor>` was an alias of `<atom:tiptap>` and emitted Tiptap JSON, so a host that came from `AsEditorContent` has `serialize(<JSON>)` in a column until `atom:tiptap-migrate` has run, and a Tiptap column can hold legacy serialized HTML. `AsTiptapContent::imageSources()` therefore reads every value both ways (HTML: quoted/unquoted `src`, `srcset`, `href`; JSON: image nodes plus any `src`/`href`/`srcset`, e.g. link marks) and never treats invalid JSON as an error.
   - **The deciding rule is a substring backstop, not that extraction.** A listed file is referenced if its file name (or its `rawurlencode`d / `urlencode`d form, or, for a name JSON writes differently, its `json_encode`d form in both hex cases: a truncated document cannot be decoded, so `tr-ünï.jpg` is stored as `tr-\u00fcn\u00ef.jpg`) appears in a stored value's raw text, its decoded text, or their percent-decoded forms (three levels). Names are unique (`random-timestamp.ext`), so this can only over-keep, and it is immune to format (CSS `url()`, `poster=`, a truncated document, `%2520` double-encoding, a src with or without the disk folder). Never replace it with a full-path or parsed-only match: that is exactly how Tiptap images, and JSON inside legacy columns, were once deleted.
   - **How the backstop stays fast.** A plain `str_contains()` of every unfound file against every row costs files x rows x value size, and orphans are never found, so they stay in the search for every row (4000 files x 10000 rows of 6 KB took 49 s, a large host would take hours). `findNamesIn()` instead splits each form of a value once into tokens (`TOKEN_SPLIT`: any run of characters that is not an ASCII letter, digit or `. _ - % +`; **every non-ASCII byte splits**, so a name beside a fullwidth colon, a curly quote, an NBSP, U+3000 or an emoji is still a token) and looks each token up in a hash of the needles, so the cost follows the length of the data. The forms are the raw and decoded value and three levels of percent-decoding, each level read with both `rawurldecode()` and `urldecode()` (a whole-value `urlencode()` writes a space as `+`). A name glued to a prefix or suffix is still found: a token is also looked up as every span that begins at its start or after a `-`, `_`, `.` or `+`, and ends at its end or before one (`thumb-NAME`, `NAME.webp`, `NAME-2x`, `a+NAME`); and a variant of each form with every JSON escape (`\uXXXX`, `\n \t \r \b \f`) turned into `/` is scanned too, so `\u002fNAME` or `\nNAME` is not glued (`JSON_ESCAPES`; a variant PCRE cannot make is skipped, the form itself is still searched). A needle that itself holds a delimiter cannot be a token, so those alone are searched as substrings: a name with a space, a quote, a bracket or **any non-ASCII character** (`日本語.png`, `tr-ünï.jpg`; their `rawurlencode`d forms are ASCII and stay on the fast path), the `json_encode`d needles (they hold a backslash), and a host-named file such as a macOS `Screenshot 2026-09-30 at 10.00.00.png` stored through `tiptapStoreImage()`. Those are slower (needles x forms x value size), so a host whose files are mostly like that gets the old cost. A value that cannot be split (PCRE limit) falls back to the substring search. **This deliberately relaxes the old "can only over-keep" invariant.** The two agree on every reference a delimiter, a non-ASCII byte, a `- _ . +` boundary or the start/end of the value bounds. The token rule no longer keeps a name that is glued to ASCII letters, digits or `%` with no `- _ . +` or delimiter between: `xNAME`, `NAMEx` (`NAME.jpgx`), `NAME` after a `%09`/`%20` that the three decode levels did not reach, or after any other alphanumeric run. The old rule kept those by accident (`photo.jpg` was "referenced" by the text `myZphoto.jpg`). None can be a reference atom itself writes: it stores a name only as the last segment of a URL or `src`, preceded by `/` (`\/`, `\u002f` and `%2F` included) and followed by a quote, `?`, `#`, whitespace, `)` or the end, and a host's own decoration (`thumb-NAME`, `thumb_NAME`, `NAME.webp`, `NAME-2x`, `a+NAME`) is bounded by one of `- _ . +`. A host that concatenates a name straight onto ASCII alphanumerics (`img123NAME`) is not seen. **A needle stands for a list of files** (`needle => names`): `a b.jpg` urlencodes to `a+b.jpg`, which can be another file's name, and a hit keeps every file the needle could stand for (over-keeping is the accepted direction; last-owner-wins used to delete the other one). `forgetNames()` removes only the found name from a shared needle. `tests/Feature/PurgeEditorImagesMatcherTest.php` holds the matcher to the old rule: it keeps the old substring matcher (as `purgeReferenceMatch()`, never in `src/`) and runs it and the production one over a seeded random corpus (HTML, JSON, CSS `url()`, `srcset`, `poster`, CSV, query strings, prefixes, suffixes, CJK punctuation, NBSP, U+3000, emoji, JSON control escapes, every encoding, truncation, whole-value `rawurlencode`/`urlencode` up to three levels, noise and near-misses). On that corpus the two keep the same set, value by value and over a whole run, when the old matcher is given the same forms; on a second corpus that adds names glued onto letters and digits and four levels of encoding, the production matcher keeps a superset of the ORIGINAL matcher's set except for names with no bounded occurrence in any form (`purgeHasBoundedOccurrence()`), and that loss is non-zero, so the test is not vacuous. The corpus draws from its own seeded `\Random\Randomizer`, so it never reseeds the global generator; its generated names start with a letter that no percent escape can supply, or a near-miss completed by the `%20` of an encoded joiner is an accident the old rule kept. If you change a delimiter, a boundary or a needle form, rerun it with more seeds. Progress is printed every `PROGRESS_EVERY` rows per model. **Memory is bounded by the value, not by its shape.** A value is tokenised `TOKEN_CHUNK` (256 KB) at a time, cut at the first delimiter past the chunk so no token spans a cut; a token's spans are walked with a sliding window of starts within the longest needle, not arrays of every boundary; and a value over `URLDECODE_MAX_BYTES` (1 MB) is not also read with `urldecode()` (the `rawurldecode()` levels still are). A 3.2 MB value of `%2B%2B+a` peaked at 79 MB (26x its size) before, 9 MB (3x) after; `PurgeEditorImagesMatcherTest` holds three shapes to under 8x. **The scan finishes before the first deletion** (`handle()` reads every model, then walks the files), so a memory fatal in it can never follow a deletion: keep every move and delete below the `getImagesFromModels()` call.
   - **The cast names the disk and folder** (`disk()`/`diskName()`/`folder()`, used by both the cast and the command). The disk's file list is taken BEFORE the database is read, so an image saved mid-scan is never called unreferenced.
   - **A column still cast as the removed `AsEditorContent` aborts the run** (`REMOVED_CAST`, compared as a string: the class is gone, and Laravel ignores a cast it cannot resolve, so the column would read as raw serialized text and its images would look unreferenced).
   - **Migration backups are referenced too.** `atom:tiptap-migrate` keeps each original in `atom_editor_backups` until `--prune-backups`, and `--restore` puts it back, so `collectBackupImages()` reads every un-restored backup on the default connection and on each connection of a scanned model through the same `collectImages()` (a backup that cannot be read, or a backup table that cannot be queried, is a problem like an unreadable model). A restored backup is not read. Keep this scan if you touch the matcher: `PurgeEditorImagesTest` ('keeps every referenced image over unmigrated, migrated and backed-up rows') turns red without it.
   - **`--grace=<hours>` (default 24)**: a file modified more recently is kept. The casts write the file on attribute assignment, not on save, so an unsaved or failed form leaves a file that is about to be referenced. `--grace=0` disables it. The grace period uses the file's **mtime**, so a file restored from backup or rsynced with an old mtime is not grace-protected.
   - **Which models are scanned** (`Commands\Concerns\DiscoversModels`, shared with `atom:tiptap-migrate`): every class declared under `app/Models` (subdirectories included; every declaration in a file counts, so an abstract base beside a model is fine; files declaring no class are skipped; an empty `--path=` is refused), plus any directory given with `--path=` (repeatable, absolute or relative to `base_path()`, e.g. a `modules/*/Models` folder). A model outside those directories is invisible, so its images look unreferenced: list its directory with `--path`. The run prints the models and columns it found; check that list before trusting a run.
   - **`tiptapStoreImage()`:** a model that defines this hook stores its images wherever the hook says. Anything outside `<disk>/editor/` is never listed, so it is never purged; anything the hook puts inside that folder is only safe if the model has an editor column the command can see.
   - **Fails safe:** a model, column, `--path` directory, model directory or disk it cannot read (a failed unserialize, a query error, an unlistable disk, an unreadable subdirectory) aborts the run before any file is touched (never "unreadable = unreferenced"); with no editor column found it deletes nothing; a file it cannot back up is kept. `--dry-run` lists what would go.

6. **`atom:tiptap-migrate` (v2) moves legacy columns to JSON, reversibly.** It reads rows with the query builder (no casts, no scopes, no events) and classifies each value in `analyse()`: *empty*; *migrated* (a Tiptap document, left alone, so a re-run is a no-op); *refused* (a serialized object or other non-string, valid JSON that is no document, the parser's reserved placeholder, over the limits, a parser failure: named, never written, not even with `--accept`); *clean*; or *lossy*. Clean vs lossy is `compareHtml()`: the original (a JSON document is rendered first) against `Content::render()` of the converted JSON, on the visible words (whitespace-insensitive) and on a tag and `tag@attribute` inventory (style as properties, class as tokens, `src`/`href` with the value). Only a **loss** counts: the editor adds attributes and renames tags (`WRAPPER_TAGS`, `TAG_ALIASES`), and an inline mark counts as lost only when it is gone altogether, because the editor merges `<s>a</s><del>b</del>` into one. Bytes the editor would change (invalid UTF-8, NUL) are a loss too. The default is a dry run; `--force` writes clean rows, `--accept=<ids|all>` also the lossy ones. **The write is the invariant:** `write()` runs per value in ONE transaction (the rows are parsed before it opens, so a lock covers two statements and one bad row cannot roll back a chunk): lock the row and re-read it (changed since it was read: left alone), `EditorBackups::store()` FIRST (it reads the backup back and compares it byte for byte, so a backup that cannot hold the value stops the write), then a query-builder `update()` (so `updated_at` and model events stay untouched), then a read-back of the new value. `Services\EditorBackups` owns `atom_editor_backups`, created on demand on the model's own connection (atom has no migration): `original` is text, or base64 when it is not valid UTF-8 or holds a NUL (`encoding`), with sha256 of the original and of the migrated value, so `--restore` can tell a row edited since (skipped unless `--discard-edits`) and writes the exact bytes back. `--prune-backups` is the only thing that deletes a backup or drops the table. `--compare` writes JSON Lines (one `json_encode()`d object per backup, nothing else, never overwrites) and no SQL but selects (a test listens). `status()` is public and callable without console input; it is what the `atom:upgrade` gate (V4-5b) reads (casts still on `AsEditorContent`, unmigrated, flagged, refused). The command must not depend on anything v4-only (it is backported to the last 3.x minor): no `Date` swap state, no trait split, no removed macros. `tests/Feature/TiptapMigrateCommandTest.php` mutation-checks each guard (update before the backup, lossy treated as clean, `updated_at` written, restore not byte-identical, no edit check, no transaction).

If you change the cast, also update the purge command's scanning logic — they are coupled.

### Actions pattern

Two entry points into the same `App\Actions\*` / `Jiannius\Atom\Actions\*` classes, sharing `Atom::resolveAction()` (dotted name → namespace via the `str()->namespace()` macro; app-level class wins over the package's):

- **`Atom::action()`** — the PHP entry point (`atom()->action()`, `$this->action()` on a component). Unrestricted: any action, and `method` in `$params` picks the method (default `handle`). The component helper is a `Component::macro()` for that reason (a `protected` trait method from v3.25.0 until v4): Livewire exposes every public method a component declares, and reflection reports a trait method's declaring class as the *using* class, so a public one was callable as `$wire.action('Any', {method: 'any'})` on every component in every host app — the same caller-picks-the-method hole v3.19.0 closed on the route, open through Livewire. A macro is not in that reflected list. `tests/Feature/ComponentTraitsSurfaceTest.php` asserts it stays off `Utils::getPublicMethodsDefinedBySubClass()` and that a real update request naming it is refused.
- **`Atom::webAction()`** — behind the public `POST /atom/action/{name}` endpoint. Runs the action only if it implements `Contracts\WebAction`; 404s otherwise, with the same body an unknown action gets so the endpoint can't enumerate an app's actions. Always calls `handle()` — `method` is stripped, never honoured. Calls the action's `authorize($params)` first if it has one, 403 on false. Denials are JSON so `ajax.js`'s `res.json()` can read them. A refusal of a class that *exists* is logged (the 404 is otherwise indistinguishable from a typo, and the failure mode in a consuming app is a silently dark front-end feature); a refusal of a class that doesn't is silent, so probing can't flood the log.

The endpoint is unauthenticated by design (guest-facing remote-option selects — `<atom:select options="countries">`, a *string* `options` prop — hit `GetOptions`), which is why the gate is per-action rather than route middleware.

`GetOptions` is the one action the package ships web-callable, so it carries a second gate of its own (v3.20.0). The requested option name used to be camelCased into a method call and interpolated into two file paths, both unvalidated — so a name could invoke any zero-arg method on a host app's subclass, or read any `.json` outside `resources/json/`. Now a name must appear in `PUBLIC_OPTIONS` (the package's own sets), `$guest` (subclass, anyone may read) or `$auth` (subclass, signed-in only, enforced by `authorize()`); anything else returns `[]`. `isOptionName()` (slug regex) guards both the dispatch and the file reads, `getFromJson()` guards the packaged-file read the same way the local one was already guarded, and it no longer writes a cache entry for a name with no file behind it (unknown names would otherwise grow the shared `_options` entry without bound). Note `authorize()` runs on the HTTP path only — `atom()->action('get-options', ...)` from a blade (`input/tel`, `select/native`) skips it, which is why the allowlist lives in `handle()` and only the auth check lives in `authorize()`. `tests/Feature/ActionEndpointTest.php` + `ActionTest.php` cover both paths; fixtures live in `tests/Fixtures/Actions/` under a dev-only `App\Actions\` PSR-4 mapping.

`Actions\GetOptions` is the in-package example. It also demonstrates the JSON lookup convention: `getFromJson($name)` reads `resource_path('json/'.$name.'.json')` from the consuming app and merges it (recursively) over `json/{$name}.json` from this package. Results are cached under `_options` in the default cache store. Adding a new option set means adding a JSON file in both places (or just one).

**Option output is escaped; the `html` key is trusted.** The listbox/filter variants render an option through `x-html="getOptionHtml(option)"`, so anything concatenated into that string is markup. `GetOptions::getOptionHtml()` therefore `e()`s the `label` and `caption` it builds (the `avatar` goes through `{{ }}` in `Blade::render`), and the client-side fallback in `resources/js/alpinejs/select.js` `escapeHtml()`s `label`, and lets `color` through `safeColor()` first (only `#hex`, `rgb(a)()`, `hsl(a)()` or a named colour — escaping alone stops attribute breakout but not `red; position: fixed`; the listbox chip template uses the same `safeColor()`); `select/native.blade.php` prints labels with `{{ }}`. An option carrying its own `html` (or `selected_html`) is returned untouched — that key is a **trusted pass-through**: the host builds it and owns escaping every interpolated field with `e()`. The raw `label` stays on the option (search filters on it, chips render it with `x-text`), so never pre-escape a label. Any new `x-html` / `{!! !!}` fed by option, label or request data needs the same treatment; `tests/e2e/select-xss.spec.js` + `GetOptionsTest` cover it (fixtures: `tests/Fixtures/XssOptions.php`, aliased to `App\Actions\GetOptions` only inside the served e2e app by `E2EServiceProvider` — never add an `App\Actions\GetOptions` file under `tests/Fixtures/Actions/`, it would shadow the package class in every Pest test — and `resources/views/e2e/select-xss.blade.php`).

### Calendar (`components/calendar/`, `src/Services/Calendar*.php`, `resources/js/alpinejs/calendar*`)

An in-house month, week and day calendar (it replaced a third-party wrapper; what the old wrapper took on the tag now throws at render: the `modes` and `periods` props, an `x-model`, and an `x-on:` or `@` listener for its seven events, listed in `$legacyEvents` at the top of `index.blade.php`; a dispatcher or listener off the tag cannot be seen, and the README's upgrade section says to search for it). Worth knowing before touching it:

- **The server hands over one JSON payload; the browser lays it out.** `Services\Calendar::payload()` builds the window (always the 6-week month grid of the anchor, whatever the view), labels, config and normalised items (`Services\CalendarItem`), and `index.blade.php` prints it on `data-atom-calendar-payload`. The Alpine factory (`x-data="calendar"`, a constant: never put a per-render value in it) reads it through a `MutationObserver`; a payload that arrives during a drag, resize or select is held and read when the gesture ends. The `items` closure is called with the window as app-timezone instants on every render, so the client can never widen a query.
- **Ownership is split.** The engine owns a `wire:ignore` body (toolbar controls, grids, day list, ghost); the server owns the root's attributes, the payload, the icon `<template>`s (icons are Blade components, so the server prints one per icon used, keyed with `wire:key`) and the host's slot. Ids are derived (a `name` hash, or component id plus property, or an engine counter), never random: an id is Livewire's morph key where it falls back to one. No `x-html` or `{!! !!}` in the calendar files (a Pest guard); text goes through `x-text`.
- **A binding inside an `x-for` clone reads only its scope variable, or fields that are stable per key.** Alpine's `queueJob` drops the re-run of an effect that already ran in the current flush. When a payload is read, a binding that also reads `labels`, `config` or the popover state runs first with the clone's old scope, and the run the refreshed scope would bring is dropped, so the label or time stays stale (#92). Strings that depend on `labels` or `config` (`nameChip()` for a chip's label, time and range; `day.label`, `day.expanded`, `day.clickable`, `column.label`, `more.label`) are therefore computed inside the `weeks` and `grid` memos (and, for the day list's rows, in the `popoverEntries` getter, which is not a memo), whose inputs include `labels`, `config` and, for the month, the open day list. Only the nested `x-for`s went stale in practice (a top-level one such as the time grid's columns refreshes its scope first), but the rule is the same everywhere. A binding to `null` never removes an `aria-expanded` Alpine already set (it writes `"null"`), so a day's is written by an `x-effect`.
- **Timezone.** The viewer's zone is `Carbon::getLocalTimezone()`, not `config('app.timezone')`. PHP converts every item to local wall-clock strings, so JS lays out by wall-clock minutes and never converts an instant (`Date.UTC` arithmetic only; no dayjs plugin, the bundle shares one dayjs). Going back is `Calendar::fromLocal()`, which is the only supported way for a host to turn an event's string into an instant. A bare `Y-m-d` is a calendar date and is never converted.
- **Structural CSS lives in `atom.css`, class strings in Blade.** Chips are placed by grid line and the day list and drag are hit-tested against that geometry, and the test rig has no Tailwind, so the grids, lanes, now line, ghost (`pointer-events: none`) and the top-layer day list are written in `atom.css`; width and the hour height sit in `@layer base` so a host utility wins. Colours and type are utilities in the Blade files (the host's Tailwind scans them); the preset palette is a PHP array in `index.blade.php`, extendable through `config('atom.calendar.colors')`.
- **One gesture at a time** (`calendar/pointer.js`, mixed into the factory). **`this.gesture` reads back as Alpine's reactive proxy of what was put there, so never compare gestures by identity** (`this.gesture === gesture` is always false); ask the gesture's own abort signal, or compare ids. The same goes for any object stored on the factory and handed to a timer or frame.
- **A host's move or resize is told through events carrying `waitUntil(promise)`**; see the README. An item is held where it was dropped (`overrides`) until the promise settles, and a payload only takes over when it differs from the last one.
- The docs demos are static (no `wire:model`); `tests/Fixtures/CalendarFixture.php` and `resources/views/e2e/calendar*.blade.php` are the served Livewire and static fixtures, and `?wired=1` wires the tag with the README Quick start's handlers. What is proven: `CalendarDocsTest` holds that tag to the README's line by line and the fixture's `create()`, `reschedule()` and `edit()` to the README class's parameter names, and `calendar-wiring.spec.js` drives a move, a resize, a select and a click through them. The README's PHP class itself is never run (its bodies are the host's), and the docs tests also tie the README's and the Boost skill's prop defaults, event detail keys and cancelability to the code.

### Design tokens (`resources/css/atom.tailwind.css`)

- **The hosts' single Tailwind import** (`@import` after `tailwindcss`; it replaces their `@source` lines and copied theme). It holds the `@source` globs, the type scale and weights (510/590), the warm zinc/gray ramp, the `--atom-*` role and tone colours in a `:root` and a `.dark` block (Pest checks every role is in both), the accent derivation, radii, density and focus. `<atom:html>` never loads it. `tests/consumer/` compiles it at 4.0.7 and the latest pin; `TokensTest.php` holds the static rules, `tokens.spec.js` and `density.spec.js` what a browser makes of them.
- **Plain `@theme static` resolves at `:root`; `@theme static inline` resolves where used**, so anything that depends on the theme or the density (roles, `accent-soft`, `accent-ink`, the three smallest sizes) is inline and a nested `.dark` or `[data-atom-density]` subtree is honoured. Inline tokens read a `--atom-*` role defined in both theme blocks; a host overrides one in its own plain `@theme`, not in a `:root` rule. **`--color-accent-content` and `--atom-focus` read `var(--atom-accent-ink)` directly, not `--color-accent-ink`**, so a host's `--color-accent-ink` override reaches the `accent-ink` utilities only, not the focus ring or `accent-content`. Deliberate: going through the `--color-*` token would pin the value at the host's scope and break a nested `.dark` island. Do not "fix" it in the CSS; the README and UPGRADE say so.
- **`@source` is narrowed, not negated**: `@source not` does not exist at the hosts' 4.0.7, so the globs name `views/{docs,mail}` and the root views, never `views/e2e` (it ships in the archive: the local-only `table-filters` route renders one). The consumer fixture adds the e2e views itself; a new view directory needs a glob (Pest checks that every directory but `e2e` is covered).
- **Fonts are self-hosted**: `atom.css` declares Geist and Geist Mono `@font-face` with a url relative to the stylesheet, so they are served by `/atom/{file}` from `dist/assets`. `<atom:html fonts>` takes one validated family (`/^[a-z0-9-]+\z/i`; anything else is no family) for the CDN link, the inline stack and the self-hosted check: `geist` (default) preloads Geist sans only (mono loads on demand), another family is a Bunny Fonts link plus `--font-sans`, `null` and `true` are the default (`geist`: a null never reaches it through the prop, since Blade's `@props` treats null as unset), and `false` loads nothing and sets `--font-sans` and `--font-mono` to system stacks (the `@font-face` rules stay, but nothing uses them, so no download).
- **Density**: `data-atom-density="compact|comfortable"` on `<body>` (`layouts.sidebar` compact, the rest comfortable; the prop is lower-cased, unknown is comfortable) or any element sets `--atom-text-*`, `--atom-control-h` and the row tokens. `@media (pointer: coarse)` then overrides control height and row min-height for every density, on `:root` and `[data-atom-density]` alike.
- **Relative-colour fallback**: `accent-foreground`, `accent-hover`, `accent-ink` and the focus ring use CSS relative colour (Chrome/Edge 119, Safari 16.4, Firefox 128), and a browser without it drops the whole property. The maths sits in `--atom-accent-*` roles and an `@supports not (color: oklch(from red l c h))` block in `@layer base`, after them, redefines only those roles with plain colours (white, the accent, a `#3b82f6` ring). The `--color-*` tokens read the roles, so a host's `@theme` override is never touched. Chromium cannot turn relative colour off, so `tokens.spec.js` injects the block's own rules. Any new token built with `oklch(from ...)` or `color(from ...)` needs an entry there (Pest lists them).

## Conventions worth knowing

- `t('Some string', $count, $params)` is the package's translation shim — accepts a plain string, number, or array; routes through `trans_choice` or `__()` appropriately. Almost every UI string in components passes through it.
- `Jiannius\Atom\Services\Carbon` is atom's immutable date (with `local()`, `pretty()`, `recent()`), used where atom builds a date itself (the calendar, the timeline, `carbon()`); it is not the app-wide date unless the host opts in with `Date::use()`. See the service-provider bullet on the date.
- Components prefer `Arr::toCssClasses([...])` over conditional class strings; conditional/utility classes are grouped by variant in plain `match` expressions (see `components/button/index.blade.php` for the canonical pattern).
- Many components dispatch and listen for window-level Livewire events prefixed `atom-` (`atom-modal-show`, `atom-toast-show`, `atom-confirm-show`, `atom-alert-show`). Search by this prefix when tracing UI state changes.
- **A prop value that lands in an HTML attribute goes through `{{ }}`, never `{!! !!}`** (`sharer`'s `data-title`/`data-url`, `embed`'s `<img src>` and `error`'s messages were the last ones, fixed in 3.29.12). Escaping does not stop a `javascript:` URL, so URL props are scheme-checked separately: `embed`'s `src` has its own gate, and `href` props go through `safe_url()` (next bullet). `tests/Feature/AttributeEscapingTest.php` parses the render, so it sees an injected attribute where a string match would not.
- The `confirm` flow for `<atom:button type="delete">` is auto-wired in the button component: it dispatches `confirmed` on accept and that translates to `$wire.delete()` unless the caller overrides `wire:click` or `x-on:click`.
- **State JS writes onto a node is stripped by a Livewire morph, unless the node is ignored or the component writes it back** (issue #56). A morph removes every attribute the server did not render, and a node whose key (`wire:key`, else its `id`) differs between the old and new markup is *replaced*, not patched. So: a popover that floating-ui positions with an inline style (`menu` with `popover`, `tooltip.content`) is morphed children-only *while it is open*, by a `morph.updating` hook in `helpers/morphed.js` (not a static `wire:ignore.self`, which would freeze a server-driven attribute or class on it for good; a closed one is patched in full and floating-ui writes its style again on the next open; the date picker's menu is a full `wire:ignore`); a node JS gives an `id` the server did not render needs a fixed `wire:key` too, or the hook is never reached and the open popover is swapped for a closed copy (`tooltip.content`); and state on a node the host owns (`data-open` on the dropdown root, `aria-expanded` / `aria-haspopup` on its trigger, a tooltip trigger's `aria-describedby`, the command palette's `hidden` / `data-active`) is written again from the DOM's truth after the morph through `onMorphed()` in the same helper, which wraps Livewire's `morphed` hook. A component registers one callback per element (stop function kept on the element, so a re-run `init()` cannot stack). The dropdown root is deliberately *not* ignored, so a server-driven class on it keeps updating. The rig has no Tailwind, so `tests/e2e/dropdown-morph.spec.js` stands in for the opacity rule and asserts computed opacity, `:popover-open` and position (`toBeVisible()` counts `opacity: 0` as visible).
- **A non-searchable select listbox handles Space itself** (`select.js` `typeAhead`), and the browser then fires a native click for Space on keyup, which the dropdown's toggle reads as a trigger click and closes the list it just opened. `typeAhead` calls `preventDefault()` on the Space keydown and the blades `keyup.space.prevent` the trigger. Any new trigger that acts on Space or Enter itself needs the same (`tests/e2e/select-keyboard-toggle.spec.js`).
- **A URL prop goes through `safe_url()` before it reaches the DOM.** Anything a component accepts as a URL (`href`, a tab or row `href`, a toast `url`/`navigate`) can hold user-supplied data, and `{{ }}` escapes the HTML but not `javascript:`. In a blade: `$href = safe_url($href);` at the top of the `@php` block, before `$href` picks the element (`$el = $href ? 'a' : 'button'`), so a blocked URL degrades to a button or a plain element instead of an anchor. In JS, `atom.safeUrl(url)` (`resources/js/helpers/safe-url.js`) at the sink (`x-bind:href`, `Livewire.navigate`, `window.open`, `location`). Both return the URL unchanged or `null` and must agree: `tests/Fixtures/safe-url-corpus.json` is the one corpus, read by `tests/Feature/SafeUrlTest.php` and `tests/e2e/safe-url.spec.js`, and its `parity` lists (about 4800 strings, sorted by what a browser-side `atom.safeUrl()` answered) fail either side that drifts. A change to either helper's rules means regenerating that file from a browser run, and checking the PHP side still matches. The 8-pass decode limit in both is a fail-closed bound; no test pins it. `safe_url()` makes a URL scheme-safe only (`//evil.com` passes), so a redirect also needs a host check. Allowed: `http`, `https`, `mailto`, `tel`, `sms`, and scheme-less URLs; a first path segment containing `:` counts as a scheme, so `foo:bar` is dropped and hosts write `./foo:bar`. `components/embed.blade.php` keeps its own scheme gate (http(s) or scheme-less) and should move onto the helper in v4.
- **Icons come from [heroicons.com](https://heroicons.com/) or [lucide.dev/icons](https://lucide.dev/icons/)** — never hand-draw a glyph or invent path data. One file per glyph at `components/icon/<name>.blade.php`: `<atom:icon._wrapper :attributes="$attributes">` wrapping a single-line 24×24 SVG. Normalise lucide's `stroke-width` from `2` to the set's `1.5`; keep its `class="lucide lucide-x-icon lucide-x"` (recent additions do). `Services\Docs::glyphs()` globs the directory and the Boost guidelines point at it rather than listing names, so **adding an icon needs no docs work** — it lists itself in `/atom/docs`.

## Development guidelines

Curated from the jiannius package skeleton (`skeleton-package`) — the subset that applies to atom. The skeleton's Pest/Testbench, Models & data, and Pint guidelines are intentionally omitted: atom has no Pint config (its Pest and Playwright suites are described under "Tests and CI") and ships no models. Front-end changes still require `npm run build` + committing `dist/` (see Front-end above).

### Conventions

- Follow the existing code conventions; when creating or editing a file, check sibling files for the correct structure, approach, and naming.
- Use descriptive names for variables and methods (`isRegisteredForDiscounts`, not `discount()`).
- Stick to the existing directory structure — don't create new base folders without approval.
- Don't change the package's dependencies without approval.
- Only create documentation files if explicitly requested.
- Be concise in explanations — focus on what's important rather than obvious details.

### PHP style

- Always use curly braces for control structures, even single-line bodies.
- Use PHP 8 constructor property promotion (`public function __construct(public GitHub $github) {}`); no empty zero-parameter constructors unless private.
- Explicit return types and type hints on all parameters: `function isAccessible(User $user, ?string $path = null): bool`.
- Prefer PHPDoc over inline comments; every public/private method gets a one-line PHPDoc. Use array-shape definitions in PHPDoc where useful.
- Backed enums mix in `Jiannius\Atom\Traits\Enum`; cases are `FULL_UPPERCASE`. The trait provides `all()`, `option()`, `label()`, `get()`, `is()`/`isNot()`, plus `color()`, `str()`, `snake()`, `slug()`.

### Workflow

- Always squash-merge when exiting a worktree, then remove the worktree.
- Plan mode: no need to use the superpowers skills.
- Session close: when closing or clearing the session, save important gotchas/findings to memory and clear any stale data pieces from it.

## Working Guidelines

Behavioral guidelines to reduce common LLM coding mistakes. For trivial tasks, use judgment.

### 1. Think Before Coding

Don't assume. Don't hide confusion. Surface tradeoffs. State assumptions explicitly; if multiple interpretations exist, present them rather than picking silently. If something is unclear, stop, name what's confusing, and ask.

### 2. Simplicity First

Minimum code that solves the problem. No features beyond what was asked, no abstractions for single-use code, no "configurability" that wasn't requested, no error handling for impossible scenarios.

### 3. Surgical Changes

Touch only what you must. Don't "improve" adjacent code or refactor things that aren't broken. Match existing style. Remove imports/variables your change orphaned; leave pre-existing dead code unless asked.

### 4. Goal-Driven Execution

Transform the task into a verifiable goal ("write a test that reproduces the bug, then make it pass") and loop until verified.

### 5. Caveman

Talk normally in discussion; talk like a caveman (caveman skill) during coding work.
